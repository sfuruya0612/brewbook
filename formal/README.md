# 認証の形式検証 (TLA+)

認証の状態遷移を TLA+ で書き、TLC のモデル検査で不変条件を検査する (ADR-0013)。
対象は、WebAuthn のチャレンジ、登録用トークン、セッション、パスキーの状態遷移である。
`auth.tla` が仕様、`auth.cfg` が検査の設定である。

## 実行方法

- `mise run formal` で TLC を実行する。`mise run check` にも含まれる。
- JDK は `mise.toml` の `[tools]` の `java` (Temurin 25) を使う。
- `tla2tools.jar` は mise のレジストリに無いため、タスクが版 (v1.7.4) と SHA-256 を固定して
  GitHub のリリースから `formal/.cache/` に取得する。jar はリポジトリに含めない (`.gitignore` の対象)。
- TLC の作業ディレクトリ (メタディレクトリ) は `-metadir formal/.cache/states` に置き、成功時は `-cleanup` で消える。
  リポジトリの直下には作らない。
- チェックサムが一致しない場合はタスクが失敗する。
  その場合は `formal/.cache/tla2tools.jar` を削除して再実行する。
  チェックサムの確認に使う `shasum` が無い場合は、その旨のメッセージで失敗する。

## モデル化した状態

| 状態 | 内容 |
| --- | --- |
| 利用者 | 定数の集合。作成直後はパスキーを持たない |
| パスキー | 利用者ごとの集合。追加、削除 (最後の 1 つは削除できない)、登録用トークンからの登録で増える |
| チャレンジ | 発行、消費、期限切れ。消費は登録とログインの両方で使う |
| 登録用トークン | 発行、使用、期限切れ。発行先の利用者に紐づく |
| セッション | 発行、ログアウト、期限切れ。ログアウトと期限切れは終了として扱う |

定数 (`auth.cfg`) は、利用者 2、パスキー 2、チャレンジ 2、登録用トークン 2、セッション 2 とする。
状態空間を有限にし、TLC の実行を短時間で終わらせるためである。

## 不変条件と要求の対応

`Inv` は、型の不変条件 (`TypeOK`) と、要求由来の次の 4 つの不変条件の連言である (`auth.tla` の `Inv`)。

| 不変条件 | 内容 | 対応する要求 |
| --- | --- | --- |
| チャレンジの 1 回消費 | 1 つのチャレンジは登録とログインを合わせて最大 1 回しか結果を生まない (結果は上書きせず蓄積する) | FR-1、FR-2 |
| トークンの 1 回使用 | 1 つの登録用トークンは最大 1 回しか使用されない | FR-1 |
| 最後のパスキーの保護 | パスキーを 1 つ以上持った利用者は、削除によって 0 個にならない | FR-3 |
| セッションの失効 | ログアウトしたセッションは要求を通さない (再び有効にならない) | FR-4 |

## 検査が機能していることの確認

不変条件の検査が実際に違反を検出することを、次の変更で確かめる。
確認はリポジトリの外に置いた `auth.tla` と `auth.cfg` のコピーで行い、リポジトリのファイルは変更しない。

- `DeletePasskey` の `Cardinality(passkeys[u]) > 1` のガードを外す。
- TLC が「最後のパスキーの保護」の違反 (パスキーが 0 個の利用者) を報告する。

同じチャレンジの二重消費は、`Register` の消費済みチェック (`c \in issuedChallenge \ consumedChallenge` の `\ consumedChallenge`) を外す変更で確かめられる。
結果は上書きせず蓄積するため、TLC はチャレンジの不変条件の違反を報告する。

この確認の実行結果は issue 0026 に記録する。
