# 統計とグラフの画面を作る

Created: 2026-09-21
Model: deepseek-v4p1-flash
対応 ADR: ADR-0007 (docs/adr/0007-frontend-flutter-web-first.md)
関連 PRD: FR-18
依存: 0010, 0013, 0014

## 背景

ADR-0007 は、統計のグラフ (PRD の FR-18) を Frontend で描画し、グラフの描画に fl_chart を使い、他のグラフライブラリを追加しないと決めた。
集計は Backend の API (0010) が行い、Frontend は集計結果を受け取って描くだけにする。
PRD は統計画面の初期状態が当月の日別の棒グラフであることと、3 か月、6 か月、12 か月、全期間、任意の期間に切り替えられることをウィジェットテストで判定することを求める。
0010 で統計の API ができ、0014 で購入の詳細の画面ができた。本 issue が統計の画面とグラフを追加する。

## 目的

利用者が、期間を選んで抽出と購入の統計とグラフを見られ、購入ごとの評価の推移を見られるようにする。

## 設計判断

- 統計画面の初期表示は、端末のタイムゾーンでの当月 1 日から当日までを日別で表示する (FR-18)。
  期間の切り替えは、当月 (日別)、3 か月、6 か月、12 か月、全期間、任意の開始日と終了日とする。
  3 か月、6 か月、12 か月は当月を含む直近の月数とし、月別で表示する。
  全期間は開始日と終了日を省略して呼ぶ。
  任意の期間は、62 日以下なら日別、それ以外は月別にする。
- 抽出日時の区切りは端末のタイムゾーンに合わせるため、クライアントは UTC オフセット (分) を API に渡す。
  値は端末のローカル時刻から UTC を引いた分数とし、日本標準時は +540 とする。
- グラフは次を統計画面に置く。
  - 抽出回数と豆の消費量の棒グラフ (月別と日別)。
  - 購入金額と重量の棒グラフ (通貨コードごとに分ける。為替換算はしない)。
  - 抽出条件と評価の関係の散布図を 4 つ (豆の量、湯量、湯の温度、時間)。
  集計結果に無い区間は描かない。条件が null の抽出はその散布図に描かない (0010 の応答)。
- 購入ごとの評価の推移の折れ線グラフは、購入の詳細の画面 (0014 が作る) に置く。
- fl_chart を追加する (ADR-0007 が定める唯一のグラフライブラリ。依存を追加する理由はここに記す)。
  その他のグラフライブラリや描画ライブラリは追加しない。
- 採らない案: 集計をクライアントで行う (全記録の取得が必要になり、ADR-0007 の「Frontend は集計結果を受け取って描くだけ」に反する)、グラフを画像としてサーバーで生成する (Worker の CPU を使い、期間の切り替えのたびに生成が必要になる)、期間のプリセットだけにする (PRD の FR-18 は任意の期間を求める)。

## 完了条件

- FR-18 の受け入れ基準のうち画面の分を満たす。
  初期状態で当月の日別の棒グラフを表示し、3 か月、6 か月、12 か月、全期間、任意の期間に切り替えられることをウィジェットテストで確認する。
- 抽出回数と豆の消費量の棒グラフ、購入金額と重量の棒グラフ (通貨コードごと)、抽出条件と評価の関係の散布図 4 つが、それぞれの系列を持つことをウィジェットテストで確認する。
- 購入の詳細の画面で、その購入の評価の推移の折れ線グラフが表示されることをウィジェットテストで確認する。
- 端末の UTC オフセットが API に渡ることをウィジェットテストで確認する (+540 の端末を模擬する)。
- `mise run check` が通過する。
