# 統計とグラフの画面を作る

Created: 2026-09-21
Model: deepseek-v4p1-flash
Completed: 2026-09-25
対応 ADR: ADR-0007 (docs/adr/0007-frontend-flutter-web-first.md)
関連 PRD: FR-18
依存: 0010, 0013, 0014

## 背景

ADR-0007 は、統計のグラフ (PRD の FR-18) を Frontend で描画し、グラフの描画に fl_chart を使い、他のグラフライブラリを追加しないと決めた。
集計は Backend の API (0010) が行い、Frontend は集計結果を受け取って描くだけにする。
PRD は統計画面の初期状態が当月の日別の棒グラフであることと、3 か月、6 か月、12 か月、全期間、任意の期間に切り替えられることをウィジェットテストで判定することを求める。
0010 で統計の API ができ、0014 で購入の詳細の画面ができた。本 issue が統計の画面とグラフを追加する。

## 目的

利用者が、期間を選んで抽出と購入の統計とグラフを見られ、購入ごとの評価の推移を見られるようにする。

## 設計判断

- 統計画面の初期表示は、端末のタイムゾーンでの当月 1 日から当日までを日別で表示する (FR-18)。
  期間の切り替えは、当月 (日別)、3 か月、6 か月、12 か月、全期間、任意の開始日と終了日とする。
  3 か月、6 か月、12 か月は当月を含む直近の月数とし、月別で表示する。
  全期間は開始日と終了日を省略して呼ぶ。
  任意の期間は、62 日以下なら日別、それ以外は月別にする。
- 抽出日時の区切りは端末のタイムゾーンに合わせるため、クライアントは UTC オフセット (分) を API に渡す。
  値は端末のローカル時刻から UTC を引いた分数とし、日本標準時は +540 とする。
- グラフは次を統計画面に置く。
  - 抽出回数と豆の消費量の棒グラフ (月別と日別)。
  - 購入金額と重量の棒グラフ (通貨コードごとに分ける。為替換算はしない)。
  - 抽出条件と評価の関係の散布図を 4 つ (豆の量、湯量、湯の温度、時間)。
  集計結果に無い区間は描かない。条件が null の抽出はその散布図に描かない (0010 の応答)。
- 購入ごとの評価の推移の折れ線グラフは、購入の詳細の画面 (0014 が作る) に置く。
- fl_chart を追加する (ADR-0007 が定める唯一のグラフライブラリ。依存を追加する理由はここに記す)。
  その他のグラフライブラリや描画ライブラリは追加しない。
- 採らない案: 集計をクライアントで行う (全記録の取得が必要になり、ADR-0007 の「Frontend は集計結果を受け取って描くだけ」に反する)、グラフを画像としてサーバーで生成する (Worker の CPU を使い、期間の切り替えのたびに生成が必要になる)、期間のプリセットだけにする (PRD の FR-18 は任意の期間を求める)。

## 完了条件

- FR-18 の受け入れ基準のうち画面の分を満たす。
  初期状態で当月の日別の棒グラフを表示し、3 か月、6 か月、12 か月、全期間、任意の期間に切り替えられることをウィジェットテストで確認する。
- 抽出回数と豆の消費量の棒グラフ、購入金額と重量の棒グラフ (通貨コードごと)、抽出条件と評価の関係の散布図 4 つが、それぞれの系列を持つことをウィジェットテストで確認する。
- 購入の詳細の画面で、その購入の評価の推移の折れ線グラフが表示されることをウィジェットテストで確認する。
- 端末の UTC オフセットが API に渡ることをウィジェットテストで確認する (+540 の端末を模擬する)。
- `mise run check` が通過する。

## 実装詳細の乖離

方式は変えず、実装の詳細として次を選んだ。

1. 「抽出回数と豆の消費量の棒グラフ」と「購入金額と重量の棒グラフ」を、単位が異なる系列 (件数とグラム、金額とグラム) を 1 つの軸に混ぜないため、系列ごとに別の棒グラフ (2 つ) に分けた。方針の「棒グラフ」は満たしており、通貨コードごとに分ける指示も守っている (為替換算はしない)。
2. 端末の時計と UTC オフセットの差し替えを `DeviceClock` (`frontend/lib/records/clock.dart`) として `RecordServices` に配る形にした。`CoffeeLogApp` と `pump_app.dart` に `clock` を追加している (ADR-0007 の「実行環境で実装が変わる依存はテストが偽の実装を差し込む」に合わせた)。
3. 「任意の期間」の入力は、ウィジェットテストで決定的に操作できるよう、カレンダーの範囲選択ではなく既存の `DayField` (文字入力とカレンダーの両方) と「適用」ボタンにした。
4. 統計画面への入口として、ホームのメニューに「統計」の項目と `/stats` の経路を追加した (画面を到達可能にするため)。
5. 統計画面の集計の読み込みは 3 経路を順に呼ぶ (並列化はしない。早すぎる最適化を避け、失敗時の対応を単純にするため)。

統計の画面とグラフを追加した。集計は Backend の API (0010) から受け取り、Frontend は描画だけを行う。

- `frontend/lib/api/stats_api.dart` を新設した (`StatsApi` と `StatsGranularity`)。4 経路の呼び出しと、期間と粒度と UTC オフセットのクエリの組み立てを持つ。`frontend/lib/api/models.dart` に `BrewPeriod`、`PurchasePeriod`、`BrewRating`、`RatingHistoryEntry` を追加した。
- `frontend/lib/records/stats_period.dart` を新設した (当月、3 か月、6 か月、12 か月、全期間、任意の期間から開始日と終了日と粒度を組み立てる純関数。任意の期間は 62 日以下なら日別、それ以外は月別)。`frontend/lib/records/clock.dart` に端末の時計と UTC オフセットの依存 (`DeviceClock`) を追加した。
- `frontend/lib/widgets/stats_charts.dart` を新設した (fl_chart の棒グラフ、散布図、折れ線グラフ)。`frontend/lib/screens/stats_screen.dart` を新設し、`frontend/lib/router/app_router.dart` に `/stats` を、`frontend/lib/screens/home_screen.dart` にメニューの項目を追加した。`frontend/lib/app.dart` と `frontend/lib/records/record_services.dart` に `DeviceClock` を配線した。`frontend/pubspec.yaml` に `fl_chart` を追加した (ADR-0007 が定める唯一のグラフライブラリ)。
- `frontend/lib/screens/purchase_detail_screen.dart` に、その購入の評価の推移の折れ線グラフを追加した。
- `frontend/lib/l10n/app_ja.arb`、`app_en.arb` と生成された `app_localizations*.dart` に、統計画面の文言 (見出し、期間の切り替え、適用、検証のエラー、グラフの見出し) を追加した。
- テストは `frontend/test/stats_screen_test.dart`、`frontend/test/stats_period_test.dart`、`frontend/test/api/stats_api_test.dart`、`frontend/test/support/fake_clock.dart` を追加し、`frontend/test/purchase_screens_test.dart` に評価の推移のグラフのテストを追加した。`frontend/test/support/fake_api.dart` に `lastQuery`、`fake_records.dart` に統計の応答のヘルパー (`brewPeriodJson`、`purchasePeriodJson`、`brewRatingJson`、`ratingHistoryJson`、`onStats`)、`pump_app.dart` に `clock` を追加した。

完了条件の検証:

- FR-18 の画面の分: `stats_screen_test.dart` の「初期状態では当月の日別の棒グラフを表示する」が当月 (`2026-09-01` から `2026-09-25`、日別) を、「期間を 3 か月、6 か月、12 か月、全期間に切り替えられる」が各切り替えのクエリを、「任意の期間を指定でき、62 日以下は日別、それ以上は月別にする」が 62 日と 63 日の境界を確認した。`stats_period_test.dart` の 7 件 (「任意の期間の終了日が開始日より前なら組み立てない」を含む) が期間の組み立てを確認した。
- グラフの系列: `stats_screen_test.dart` の「抽出回数と豆の消費量の棒グラフがそれぞれの系列を持つ」「購入金額と重量の棒グラフが通貨コードごとの系列を持つ」「抽出条件と評価の関係の散布図 4 つが条件ごとの系列を持つ」が、棒の値と散布図の点 (条件が null の抽出は除外) を確認した。
- 評価の推移: `purchase_screens_test.dart` の「詳細でその購入の評価の推移の折れ線グラフを表示する」が、折れ線の点の x (応答の並びの添字) と y (評価) を、「詳細で評価の推移の読み込みに失敗すると再試行を促す」が失敗時の表示と再試行を確認した。
- UTC オフセット: `stats_screen_test.dart` の「端末の UTC オフセット (+540) を API に渡す」が、+540 の端末で抽出の 2 経路に `utc_offset_minutes=540` が渡り、購入の経路には渡らないことを確認した。`stats_api_test.dart` の 6 件がクエリの付与と応答の読み取りを確認した。
- `mise run check`: exit 0 (ベースラインからの新たな失敗は無し)。

方針からの乖離 (方式は変えていない): 1 から 5 は issue の「## 実装詳細の乖離」に記載済みで、6 と 7 はレビューの指摘への対応として本 close で追記した。

1. 棒グラフを系列ごとに分けた。単位が異なる系列 (件数とグラム、金額とグラム) を 1 つの軸に混ぜないためである (通貨コードごとに分ける指示は守る)。
2. `DeviceClock` を導入した。端末の時計と UTC オフセットをテストで差し替えられるようにするためである (ADR-0007 の依存の差し替え)。
3. 任意の期間の入力は `DayField` と「適用」ボタンにした。ウィジェットテストで決定的に操作できるようにするためである (カレンダーの範囲選択はテストしにくい)。
4. ホームのメニューに「統計」の項目と `/stats` を追加した。画面に到達できるようにするためである。
5. 集計の読み込みは 3 経路を順に呼ぶ (並列化はしない)。早すぎる最適化を避け、失敗時の対応を単純にするためである。
6. 期間の切り替えが重なったときは古い読み込みの応答を捨てるようにした (最新の期間の表示を古い結果で上書きしないため。世代の管理。同じ扱いを購入の詳細の読み込みにも入れた)。任意の期間の終了日が開始日より前の場合は `statsPeriodFor` が `ArgumentError` を投げるようにした (画面の検証と同じ前提を関数にも持たせるため)。
7. テストの補助として `FakeApi` に応答を 1 回だけ保留して解放する仕組みを追加し、読み込みが重なる状況を再現できるようにした。統計画面と購入の詳細それぞれに、保留した古い応答を解放しても表示が上書きされないことを確かめるテストを追加した (世代の判定を外すとどちらのテストも落ちることを確認した)。4 つの散布図それぞれの null の除外と、集計が空の区画の「記録がありません」の表示もテストした。

なお、`StatsApi._objects` が配列の要素でオブジェクトでない値を読み飛ばす点は、既存の `RecordsApi._objects` と同じ実装であり、統計側だけ変えると規約が二重になるため、既存の慣習に合わせて残した (指摘として記録)。
