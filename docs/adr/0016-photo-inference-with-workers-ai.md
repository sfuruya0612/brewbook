# ADR-0016: 写真からの購入と商品の推測に Cloudflare Workers AI を使う

Created: 2026-09-30
Model: DeepSeek V4.1 Flash
Status: Accepted

## 背景

PRD の FR-10 は、購入にパッケージ写真を 1 枚添付できるとする。
写真はクライアントで JPEG に変換し、R2 へ直接アップロードし、Backend は署名付き URL の発行と完了の通知だけを扱う (ADR-0003)。
2026-09-30 に所有者が、写真を選んだときに写るパッケージから購入と商品の項目を推測したいと求め、PRD に FR-19 を追加した。
推測には画像を入力にできる AI モデルが要る。

利用者向けの Worker は Rust (workers-rs) で Cloudflare Workers 上にあり、依存を可能な限り少なくする方針である (ADR-0001)。
Cloudflare Workers AI は Worker のバインディングから vision モデルを呼べる。
workers-rs の 0.8.6 は AI バインディング (`env.ai("AI")` と `Ai::run`) を持ち、Rust のクレートを追加する必要が無い (2026-09-30 に手元のクレートのソースで確認)。
Workers AI は無料枠 (1 日 10,000 Neurons) を持ち、顧客コンテンツをモデルの学習に使わない (2026-09-30 に Cloudflare のドキュメントで確認)。

## 決定

- 利用者向けの Worker に Workers AI のバインディング (`AI`) を追加し、写真から購入と商品の項目を推測する (FR-19)。
- 推測は購入の保存の前に行い、結果は候補として返す。
  自動では保存せず、利用者が画面で確認して適用する。
- 入力は、クライアントが変換済みの JPEG (長辺 2048 px 以下、5 MB 以下。FR-10) とする。
  写真の保存の経路 (R2 への署名付きアップロード) は変えない。
- 経路は `POST /api/purchase-suggestions` とし、認証を必須にする。
- モデル名は vars で環境ごとに差し替えられるようにする。
  既定値は、無料枠で使える vision モデルから、実写真での比較で決める (未確定論点)。
- 課金は発生させない。
  Workers AI の無料枠 (1 日 10,000 Neurons) の範囲で動かし、Workers Paid には加入しない (ADR-0015)。
  無料枠を超過したときは推測の呼び出しが失敗し、利用者は手入力で続けられる。
- モデルの出力はサーバー側で検証し、形式に合わない項目は null に落とす。
  生の出力は保存せず、ログにも出さない。
- 写真は Cloudflare 内で処理し、外部 (Cloudflare 以外) の AI サービスには送らない。

## 検討した選択肢

| 選択肢 | 採用しない理由 |
| --- | --- |
| 外部の AI サービス (OpenAI、Google など) の vision モデルを使う | ベンダーと契約と API キーの管理が増える。写真が Cloudflare の外に出る。無料枠の管理が別になる |
| クライアント (ブラウザ) で推論する | Web で vision モデルを動かす現実的な基盤が無い。モデルの配布 (数十 MB 以上) と性能の問題がある (ADR-0007) |
| 推測せず手入力だけにする | 所有者の要望に反する (FR-19) |
| R2 にアップロード済みの写真 (`pending/`) を推論に使う | 購入に紐づける前の写真を推測の API に渡す経路と、あとから購入に紐づける変更が必要になる。写真を直接送る案は経路 1 つの追加で済み、写真の保存の経路を変えない |
| 写真のアップロードの完了通知 (FR-10) の応答で推測を返す | その時点で商品を選び終えており、商品の項目の推測を入力に活かせない |
| Workers AI の有料のモデル (kimi、glm、deepseek-v4 など) を使う | 課金が発生する (Workers Paid か AI Gateway のクレジットが要る)。ADR-0015 の無料枠の方針に反する |

## 結果

- 推測は Workers AI の推論に依存し、応答に数秒かかる。
  クライアントは推測中の表示を出し、保存の操作を妨げない (FR-19)。
  推論の待ちは Worker の CPU 時間を消費しない。
- 推論の入力の形式 (messages 内の画像の表現、バイト列、base64) はモデルごとに異なる。
  実装で確認する (issue 0034)。
- 精度は保証されない。
  利用者が確認して適用する前提とし、外れた場合は手入力で訂正できる。
- 無料枠と 1 回あたりの消費の推定は次の通りである。
  Neurons の単価は 1,000 Neurons あたり $0.011 で、無料枠は 1 日 10,000 Neurons である。
  無料枠はアカウント単位で、staging と production の Worker が共有する。
  変換済みの写真 1 枚 (長辺 2048 px) の tokens 数は、llama-3.2-11b-vision は 560 px のタイル 4 枚で約 6,400、moondream3.1 は約 1,000、それ以外 (llama-4-scout、mistral-small-3.1、qwen3.8) は約 2,000 と仮定する。
  プロンプトは約 300 tokens、出力 (JSON) は約 200 tokens と仮定すると、1 回あたりの消費はモデルにより約 40 から 150 Neurons (約 $0.0004 から $0.0017。1 ドル 150 円換算で約 0.07 円から 0.25 円) と見積もる。

  | モデル | 入力 (Neurons / M tokens) | 出力 (Neurons / M tokens) | 1 回の推定 (Neurons) |
  | --- | --- | --- | --- |
  | `@cf/meta/llama-3.2-11b-vision-instruct` | 4,410 | 61,493 | 約 40 |
  | `@cf/moondream/moondream3.1-9B-A2B` | 27,273 | 90,909 | 約 55 |
  | `@cf/meta/llama-4-scout-17b-16e-instruct` | 24,545 | 77,273 | 約 70 |
  | `@cf/mistralai/mistral-small-3.1-24b-instruct` | 31,876 | 50,488 | 約 85 |
  | `@cf/qwen/qwen3.8-27b` | 40,909 | 290,909 | 約 150 |

  画像の tokens 数はモデルごとの前処理に依存し、上の見積もりは仮定を含む。
  実測は実装で行い、結果を issue に記録する (未確定論点)。
  無料枠は 1 日 10,000 Neurons であるため、1 日あたり 65 から 250 回の推測ができる計算になる。
  想定規模 (利用者 20 人、1 人あたり月 4 回の購入) で全ての購入に推測を使うと 80 回/月であり、無料枠に収まる。
- AI の呼び出しは CI で実行できない (Cloudflare のアカウントとネットワークが要る。0009 の R2 の検証と同じ扱い)。
  プロンプトの生成と応答の解析は `brew_book_core` の単体テストと PBT で検証し、AI を呼ぶ経路は手元で検証して結果を issue に記録する。
- ローカルの `wrangler dev` の AI バインディングはリモートの推論に接続する (wrangler の remote binding)。
  ローカルでの検証もアカウントの無料枠を消費する。
  ログインの無い CI でバインディングを持つ `wrangler dev` が起動できるかは未確認である (未確定論点)。

## 追記 (2026-09-30 の実装)

- `wrangler dev` と AI バインディングの関係を実装時に確認した。
  AI バインディングはローカルでもリモートの推論に接続し、起動時にリモートのプロキシのセッションを開く。
  そのため、認証情報の無い CI ではトップレベルの AI バインディングを持つ `wrangler.toml` で `wrangler dev` が起動しない。
  結合テストのハーネス (`backend/brew_book/tests/support/mod.rs`) は `wrangler dev --local` で起動し、リモートのバインディングを無効にする。
  `--local` では AI の呼び出しは失敗し、推測の API は 500 を返す (この経路は結合テストで確認する)。
  開発者の `mise run dev` は `--local` を付けず、ログインのある環境で実際の推論に接続する。
- バインディングに `remote = true` は付けない。
  この環境ではリモートのプロキシのセッションの起動が、アカウントの選択 (複数のアカウント) や workers.dev のサブドメインの条件で失敗し、`wrangler dev` が起動しなくなる。
- 推論の入力は `messages` の content に `text` と `image_url` (data URL) を並べる形とし、`max_tokens` 512 と `temperature` 0 を付ける。
- モデルは vars の `AI_SUGGEST_MODEL` とし、既定値は 2026-09-30 の実写真 (3 枚) と合成ラベルでの比較で `@cf/meta/llama-4-scout-17b-16e-instruct` に決めた (名前の抽出の精度、所要 約 4 秒、1 回あたり 約 62 Neurons。他は mistral-small-3.1 が約 89 Neurons、qwen3.8 が約 277 Neurons で不安定、llama-3.2-11b-vision は商品名が null、moondream3.1 は messages 形式に非対応。issue 0034)。
- 2026-09-30 の実装環境では、Workers AI の呼び出しがアカウント側の `internal error` で失敗した (テキストのモデルでも同じ)。
  実写真での候補モデルの比較と、手元の `wrangler dev` での推測の確認はできなかった (issue 0034 の調査タスク)。
