# ADR-0012: 負荷試験に k6 を使い、ローカルの認証が不要な経路を VU 50 で叩く

Created: 2026-09-26
Model: DeepSeek V4.1 Flash
Status: Accepted

## 背景

PRD の性能は、店、商品、購入、抽出の一覧と単件取得の API の p95 を 200 ms 以内と定める。
この確認は、リリースの後に Workers Logs の保持期間の全量 (Workers Free プランは 3 日、Workers Paid プランは 7 日) で p95 を集計する方法しか無い。
本番へのデプロイがまだ無いため、実施していない。
リリースの前に、クエリやキャッシュの変更が応答時間に与える影響を手元で確かめる手段も無い。

所有者が 2026-09-26 に、k6 で VU 50 の簡単な負荷試験を行うことを決めた。
k6 は mise のレジストリから取得でき、同日時点の版は 2.3.0 である。
認証が不要な経路は、`/api` の経路の台帳で `auth_required` が false の 4 つ (登録の開始と完了、ログインの開始と完了) だけである。

## 決定

- 負荷試験の道具は k6 とし、版は `mise.toml` の `[tools]` で 2.3.0 に固定する (ADR-0009)。
- 対象はローカルの `wrangler dev` (`mise run dev` が配信する `http://localhost:8787`) だけとする。
  本番 (workers.dev) は対象外とする。
  誤って本番に負荷をかけることを防ぐ。
- 負荷は VU 50 の定常 1 分とし、認証が不要な経路だけを叩く。
  対象は次の 4 つとする。
  - `GET /` (Flutter のビルド成果物の index.html)
  - `GET /main.dart.js`
  - `GET /flutter_bootstrap.js`
  - `POST /api/auth/login/begin` (入力を持たず、D1 への書き込みを含む経路)
- 認証が不要な 4 経路のうち、登録の開始と完了、ログインの完了は有効な入力 (登録用トークン、クレデンシャル) の組み立てを要する。
  この 3 経路は対象外とし、入力を持たないログインの開始だけを対象にする。
- 状態を変更する API は `Origin` ヘッダを検証する (0017)。k6 は `Origin` を自動で付けないため、`POST` には `Origin: http://localhost:8787` (既定の `BASE_URL` と同じオリジン) を付ける。
- 認証が必要な経路は対象にしない。
  認証はパスキーだけであり、k6 からセッションを作るにはセッションの行を D1 に直接入れる下ごしらえが要る。
  それは「簡単な負荷試験」の範囲を超える。
- 閾値は、失敗率 (`http_req_failed`) が 1% 未満、応答時間の p95 が 500 ms 未満とする。
  PRD の p95 200 ms は本番の Workers Logs の集計で判定するため、ローカルの負荷試験では緩い目安とし、結果を記録する。
- シナリオは `load/k6/load.js` に 1 つのファイルとして置く。
  対象のオリジンは `BASE_URL` で受け取り、既定値を `http://localhost:8787` とする。
- 実行は `mise run load` とする。
  タスクは k6 の実行だけを行い、`wrangler dev` の起動は含めない。
  起動のコマンドラインは `mise run dev` に 1 つだけ持つ (ADR-0009)。
- `mise run check` には含めない。
  check は既に 27 分前後かかり、負荷試験には `wrangler dev` の起動と 1 分の実行が加わる。
  リリースの前に所有者が手動で実行する。
- 結果 (実行日時、p95、失敗率) は issue に記録する。
  閾値を満たさない場合は、原因 (ローカルの資源の不足、シナリオの誤り) を調べて記録する。
  閾値を緩める場合は、本 ADR の改訂として所有者に確認する。

## 検討した選択肢

| 選択肢 | 採用しない理由 |
| --- | --- |
| 認証が必要な経路も対象にする | セッションの行を D1 に直接入れる下ごしらえが必要になり、試験の手順が増える。最初の負荷試験の対象としては過剰である |
| 登録の開始と完了、ログインの完了も対象にする | 有効な入力 (登録用トークン、クレデンシャル) の組み立てが必要になり、「簡単な負荷試験」の範囲を超える |
| 本番の Worker を対象にする | 所有者の本番の Worker に負荷がかかる。誤実行を防ぐ仕組み (別の環境変数と確認) を別途用意する必要がある |
| CI で実行する | `wrangler dev` の起動と 1 分の負荷が CI に加わる。共有の runner の性能は変動し、閾値が不安定になる |
| wrk、vegeta、autocannon を使う | 所有者が k6 を選んだ。k6 はシナリオを JavaScript で書き、閾値を宣言でき、mise で版を固定できる |

## 結果

- リリースの前に、手元で `mise run dev` を起動してから `mise run load` を実行し、p95 と失敗率を確認できる。
- 本番の p95 の判定は、引き続き Workers Logs の集計で行う。
  負荷試験の結果では代用しない。
- 変更は issue 0025 で行う。
- 負荷試験の対象を認証付きの経路に広げる場合は、下ごしらえの方法 (テスト用のセッションの作成) を定める ADR を追加する。
